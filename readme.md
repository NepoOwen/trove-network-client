# network-nepofied

A clean-room, reverse-engineered C++20 client for Trove's login/world network
protocol. It authenticates against Glyph, logs into an auth server, completes
the world handshake, joins a channel, and exposes a small "playground" API
(`api::ApiHandler`) for sending and observing arbitrary `NetEvent`/`SessionData`
traffic once a live world connection exists.

It is not a renderer or a game client in any visual sense -- there is no game
world, no assets, no UI. It is a protocol-level bot: enough of the client-side
state machine to end up with an authenticated, keep-alive'd connection to a
Trove world server, plus hooks (hotkeys) for poking at that connection.

## How a run works

1. **Glyph HTTP login** (`login/`) -- POSTs credentials to
   `auth.trionworlds.com`, handles 2FA, and parses out an auth ticket (XML +
   signature). The ticket is cached to disk so subsequent runs don't need to
   re-authenticate with Glyph.
2. **Auth server** (`auth/`) -- opens a raw TCP connection to one of the
   region's auth servers, performs the version handshake, sends the cached
   ticket, and waits for the server to assign a world server address.
3. **World server** (`world/`) -- connects to the assigned world server,
   repeats the handshake, sends the login payload, solves the server's
   challenge-response check, and joins a channel.
4. **Post-login server** (`world/post_login_handler.*`) -- a third, short-lived
   connection opened partway through step 3 to acknowledge the login and fetch
   map data, running in parallel with the world connection.
5. **Playground** (`api/`) -- once the world connection is fully up,
   `ApiHandler` is live: it can send hand-built `NetEvent`/`SessionData`
   messages and every message it sees is fully decoded and printed.

Every connection in steps 2-4 uses the same framing/encryption layer
(`utils/frame`, `utils/crypto`) and the same custom wire format
(`utils/proto`) -- `network::Connection` is the common wrapper tying a raw
socket to that framing state.

## Folder/file reference

### `src/main.cpp`
Entry point. Just calls `app::run(argc, argv)`.

### `src/app/` -- top-level CLI flow
- **session.cpp/.hpp** -- parses argv into one of three modes (see
  "Usage" below), loads a cached ticket, picks auth servers for the region,
  and drives the `auth::AuthHandler` for the lifetime of the run.
- **selftest.cpp/.hpp** -- `--selftest` mode: round-trips the AES-CFB cipher
  against a known plaintext/ciphertext pair and the DEFLATE/INFLATE
  implementation against synthetic data, to catch a broken build before
  spending a login attempt on it.

### `src/login/` -- Glyph HTTP authentication
- **login.cpp/.hpp** -- builds and sends the `multiauth` POST request
  (WinHTTP on Windows, libcurl elsewhere), parses the response (auth ticket
  XML, signature, 2FA requirement, error codes), and persists/loads cached
  tickets under `auth/<account_id>_raw.bin`.

### `src/auth/` -- auth-server protocol
- **auth_handler.cpp/.hpp** -- the auth connection's state machine: version
  handshake, login, 2FA-era token exchange, parses the `NM` channel messages
  the server uses to assign a world server and a channel id, and hands off to
  `world::WorldHandler` once a world server address is found.
- **auth_messages.cpp/.hpp** -- builds the raw auth-protocol messages
  (handshake, login, the post-handshake "followup" SessionData) from the
  ticket/account fields.

### `src/world/` -- world-server protocol
- **world_handler.cpp/.hpp** -- the world connection's state machine:
  handshake, pre-challenge ack, world login, the anti-cheat challenge
  response, channel join, and dispatching decoded messages (net events,
  leaderboard/market data, local-player-loaded, spawn) to the live
  `api::ApiHandler` once one exists.
- **post_login_handler.cpp/.hpp** -- the short-lived third connection: sends
  the post-login ack, waits for map data, and answers its own copy of the
  anti-cheat challenge if the server asks for one on this connection too.
- **world_messages.cpp/.hpp** -- builds the raw world-protocol messages
  (handshake, login, challenge response, channel join, ready) and the
  `LoginFields` struct carrying the session nonce/signature/ticket XML.

### `src/api/` -- the post-login "playground"
- **api_handler.cpp/.hpp** -- `ApiHandler`: sends arbitrary `NetEvent`s (on
  the world connection) and `SessionData`s (on the auth connection), tracks
  the client's own world entity id (`self_id`, needed as the actor for sent
  events), and logs every message it sends or sees via `proto::dump`.
- **api_messages.cpp/.hpp** -- the typed-param encoding for `NetEvent`
  (`EventParam`/`ep_*`) and `SessionData` (`SessionField`/`sdf_*`), mirroring
  what `utils/proto`'s decoder reads back.
- **hotkeys.cpp/.hpp** -- Windows-only (`GetAsyncKeyState`) F-key bindings that
  fire canned `send_net_event`/`send_session_data` calls through a live
  `ApiHandler`, for interactively poking at the connection without a rebuild.
  A no-op stub on other platforms.

### `src/network/` -- transport-agnostic plumbing shared by all three connections
- **connection.cpp/.hpp** -- `network::Connection`: pairs a `net::Socket`
  with a `frame::Channel` (the per-connection crypto/inflate state) so every
  handler talks through one object instead of juggling both separately.
- **log.cpp/.hpp** -- all console logging, including `log_status()` which
  mirrors the real client's `$LoadingStatus_*` loading-screen text.

### `src/utils/` -- protocol-independent building blocks
- **net/** -- raw blocking TCP socket (`net::Socket`), portable over
  WinSock/BSD sockets, plus `host:port` parsing and startup/teardown.
- **crypto/** -- a from-scratch AES-128 implementation and the CFB streaming
  mode used for every connection's encryption (`crypto::Stream`).
- **zlib/** -- a from-scratch DEFLATE encoder and an INFLATE decoder (both
  one-shot and streaming, since the game's compression spans multiple
  frames per connection) -- no dependency on the real zlib.
- **frame/** -- the `[len][flag][ciphertext]` segment framing every
  connection uses, built on `crypto`/`zlib`/`chall`.
- **proto/** -- the clean-room decoder/encoder for the custom
  protobuf-like wire format every message body uses: tag/field/wire-type
  parsing, the typed `NetEvent` param list, leaderboard/market record array
  decoding, and `proto::dump()`, the recursive pretty-printer used for all
  traffic logging.
- **xigncode/** -- solves the world server's anti-cheat heartbeat challenge
  (`xem::solve`), invoked by `world_handler.cpp` and `post_login_handler.cpp`
  whenever a challenge message arrives. **Off-limits**: `challenge.hpp` is not
  to be opened, viewed, or modified as part of ordinary maintenance of this
  repo.

## Usage

```
network-nepofied --selftest
network-nepofied --login <email> <password> [2fa-code]
network-nepofied [region] [account_id]
```

- `--selftest` runs the crypto/deflate self-checks and exits.
- `--login` authenticates with Glyph and caches the resulting ticket under
  `auth/<account_id>_raw.bin`. If Glyph requires a 2FA code and none was
  given, it reports which kind (email/mobile) and exits so you can rerun
  with the code.
- The default mode loads a cached ticket and runs the client against
  `region` (`EU` (default), `NA`, `PTS`, or a literal `host:port`).
  `account_id` can be omitted if `auth/` has exactly one cached ticket. If
  none are cached yet, it prompts for email/password/2FA code on stdin and
  logs in before continuing -- no need to run `--login` separately first.
  If more than one account is cached, pass `account_id` explicitly.

Once connected, if built for Windows, the F-key hotkeys in `api/hotkeys.cpp`
are live (see that file for the current bindings).

## Environment

### Windows

- **network-nepofied.sln** / **network-nepofied.vcxproj** -- Visual Studio
  solution, locked to a single **Release | x64** configuration (no Debug
  config is defined). Toolset v145, C++20, links `ws2_32`, `winhttp`,
  `user32`.
- **network-nepofied.vcxproj.filters** -- organizes the Solution Explorer
  tree to mirror the `src/` folder layout.
- Open the `.sln` in Visual Studio 2022+ and build; the binary (and all
  intermediate `.obj`/`.pdb` files, under `build\obj\`) lands in `build\`.

### Linux (and any other non-Windows target)

- **CMakeLists.txt** -- builds the same sources with CMake. Requires
  libcurl (used in place of WinHTTP for the Glyph HTTP request) and
  pthreads; the hotkey module compiles to a no-op stub since
  `GetAsyncKeyState` doesn't exist outside Windows.

```bash
sudo apt install libcurl4-openssl-dev   # or your distro's equivalent
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/network-nepofied --selftest
```

The binary and CMake's own build files (`CMakeFiles/`, caches, etc.) all
live under `build/`, same as the `.vcxproj`.

### Both platforms

- C++20 is required (structured bindings, etc. are used throughout).
- On startup the binary `chdir`s to its own directory (resolved via
  `GetModuleFileNameW` on Windows, `/proc/self/exe` on Linux) before doing
  anything else, so `auth/<account_id>_raw.bin` always lands next to the
  executable -- not wherever the caller's current directory happened to be.
  No setup needed; just run the binary and `auth/` is created alongside it
  the first time you log in.
- No game assets or external data files are required; everything the client
  needs is built into the binary or received over the wire.
